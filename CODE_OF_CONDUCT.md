# Code of conduct

## Scope

This applies to the issue tracker, pull requests, discussions and any other space where someone is
speaking on this project's behalf.

## The expectation

Argue about the code, the measurement and the evidence. Do not argue about the person writing it.

Concretely:

- **Criticism of a claim is welcome and expected.** This project's whole premise is that unmeasured
  claims are worthless, so holding it to that standard is participating, not attacking.
- **Say what you measured and how.** "This did nothing for me" is a useful report; "this is snake oil"
  is not, and neither is "works great, thanks".
- **Assume the other person is competent until shown otherwise.** Most disagreements here are about
  conditions - a different CPU topology, a different driver, a different workload.
- **No harassment, slurs, personal attacks, or sustained disruption.** Not in public, not in private
  messages to contributors.

## Hardware disagreement is normal here

Two people with the same app, the same settings and different CPUs will get different results, because
interrupt topology differs per machine. A report that something did not improve is valuable data, not an
accusation. Treat it that way.

## Enforcement

Report a problem to the maintainer through the contact on the GitHub profile, or through a
[private security advisory](https://github.com/Kareem-Shabaka/stutter-guard/security/advisories/new) if
you would rather not be seen reporting it.

The maintainer will remove, edit or reject contributions that do not meet this standard, and will say
which rule was broken. Persistent disregard ends participation.
