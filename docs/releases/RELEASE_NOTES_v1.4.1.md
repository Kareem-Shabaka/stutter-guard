# Stutter Guard v1.4.1 - Release Notes

Released from `main` at the commit this tag names. Version stamped `1.4.1` in
`Directory.Build.props`; the `FileVersion` of the binary is `1.4.1.0`.

**This is a patch release. Install it if you run 1.4.0.** Three of the fixes below are defects in 1.4.0
itself, and one of them means the report button in 1.4.0 has never worked.

---

## Read this if you ever pressed "Submit hardware report" or "Send feedback"

In 1.4.0, and in every release before it, those two buttons sent nothing. Two webhook addresses were
compiled into the program, both addresses were published in this repository, a public-repository scanner
found them on 2026-11-15, and the service deleted both permanently. Every submission after that failed
with HTTP 404, and the app reported it as `Submission returned status NotFound.`

1.4.0 also shipped those two dead addresses *inside the binary*, which is why they had to be deleted at
the service rather than merely edited out here: a credential that reaches a release artefact cannot be
un-leaked.

**What 1.4.1 does instead:** no address is compiled in. The app asks for one the first time you use
either button, stores it on your machine, and only ever uses it for a report you approved. With none set,
it saves the report to a file and says so. A build can also carry an address supplied at build time from
a file that is deliberately excluded from this repository - that is how the official release is
provisioned, and it is why the address no longer appears in the source.

---

## Fixes

| Defect | Effect in 1.4.0 |
| :--- | :--- |
| **A credential was committed to a public repository** | Two webhook URLs sat in `Reports/TelemetryClient.cs`. They were indexed, found, and revoked. Any fork or clone carries them forever. Now nothing is compiled in. |
| **Reporting had silently stopped working** | Both destinations returned 404, and the message the user saw named an HTTP status rather than the reason. A 404 now says the address no longer exists and that a publicly posted webhook is deleted permanently. |
| **The preview could print your own secret** | Redaction only recognised Discord-shaped addresses. For any other destination the "here is exactly what will be sent" panel printed the full address, including its token - and the preview is what people paste into an issue when asking for help. Every https address is now redacted to its last path segment. |
| **Base64 on the command line** | Every internal PowerShell call used `-EncodedCommand`, i.e. base64 script text in a command line. "Unsigned binary runs PowerShell with a base64 script and an execution-policy bypass" is the canonical dropper signature, and it is half of what earned this build a Trojan-Downloader verdict from one engine. The script is now a temporary `.ps1` you could read before it runs, and it is deleted afterwards. |

## Also in this release

| Change | Detail |
| :--- | :--- |
| **Two separate destinations** | Bug reports and feedback can go to different addresses. Feedback falls back to the report address when unset. |
| **Signing, wired end to end** | `sign.cmd` signs a local build with `signtool`, timestamps it, and verifies with `/pa`; with no certificate configured it exits 2 and says the file is unsigned rather than implying otherwise. The release workflow signs before uploading and fails the release if a configured identity does not verify. |
| **The checksum file stops quoting a figure** | 1.4.0's notes recorded a clean-build hash as though a commit had one. It does not: the same commit rebuilt hours later produced a different file, and `--verify-repro` cannot see that because both of its publishes share one tree. The file now records what was measured and what it does not prove. |

beside it. Verify a download against that file.

## What this release does not fix

- **The binary is not code-signed**, and Windows SmartScreen will warn on a downloaded copy. `sign.cmd`
  and the workflow step are ready; a certificate is the missing input.
- **The Trojan-Downloader detection is not gone.** Removing the base64 command line and the hardcoded
  endpoint removes two indicators. The program still copies itself into `ProgramData`, schedules a SYSTEM
  task to re-apply one tweak after each boot, and downloads a test file during the interrupt check. Those
  are genuine behaviour, not obfuscation, and a vendor may still cite them. Signing plus a false-positive
  submission is the route that actually clears a verdict.
- **1.4.0's asset remains published** with the two dead addresses inside it. They are revoked and
  unrecoverable, so there is nothing to act on, but the record should be honest about what it contains.

## Upgrading

Nothing in the persisted format changed: journal format 2, the same tweak ids, the same per-tab tier map.
Your journal, `undo-all.ps1` and recorded originals are untouched. The only new option is the reporting
address, which starts empty and is filled in the first time you send something.

Full detail of every change is in the commit history; this file states what the release does.
